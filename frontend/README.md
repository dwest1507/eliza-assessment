# Research workspace (front-end)

The Next.js research workspace: an analyst asks a question, or clicks a starter prompt, watches the answer stream in, and clicks any `[Sn]` citation to open that Source's passage in a side panel. It sits on the stack of the developer's portfolio: Next.js (App Router), Tailwind CSS and the AI SDK's `useChat`. It shares the portfolio's look as well: a dark canvas with a faint grid and an ambient glow, glass cards, Inter with monospaced labels and a sky-blue accent, all defined as theme tokens and a few component classes in [`app/globals.css`](app/globals.css).

Run it from the repo root with `make dev`, which starts the chat API and this app together (see the root [README](../README.md#running-the-full-stack)).

## How it talks to the backend

The browser never calls the chat API directly. `useChat` posts the conversation to this app's own route, [`app/api/chat/route.ts`](app/api/chat/route.ts), which forwards the last messages the prompt uses (the question and the 10 before it, the backend's `HISTORY_TURNS`; older ones are dropped, so a long conversation keeps working), each with its role and text (and, for an earlier answer, the Filing ID each of its Source tags cited, never the passages) to the API's `POST /api/chat` (it reads them with the same helpers in [`lib/chat.ts`](lib/chat.ts) that the workspace uses to read a message's text, Sources and data parts) and streams the API's [AI SDK UI message stream](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol) back unchanged. The API's URL therefore stays on the server. It comes from `BACKEND_URL` (copy [`.env.example`](.env.example) to `.env`); when unset it is `http://127.0.0.1:8000`, where `make api` listens. `make dev` sets it to the API it starts.

Each answer shows only its opening paragraph at first: the direct answer of two or three sentences that the prompt's fixed structure puts first. "Show full analysis" reveals the rest (the per-Company detail, tables and the closing Coverage note), and works while the answer streams, showing the rest live; until the answer completes, the control says the rest is still being written. [`lib/chat.ts`](lib/chat.ts) splits the text at its first blank line, and doesn't split an answer with one paragraph or one whose first block is a heading, list item or table row, which then shows whole with no control. The expanded state is each answer's own and isn't saved, so a restored answer starts collapsed. Each Coverage Gap shows in a callout above the answer, headed in plain words ("What these Filings can’t answer", with the term Coverage Gaps on hover and as its accessible name); the answer's closing Coverage note, which repeats the gaps, falls in the full analysis, so the default view states each gap in the callout (and the opening may mention it too, since the prompt is unchanged).

The stream carries the Query Scope and the numbered Sources as data parts before the answer text, so every citation is clickable while the answer is still arriving, in the short answer as in the full analysis. Nothing else shows beneath an answer until it is complete (every answer is, except the last one while the chat is waiting for or streaming it; a restored answer always is), so the screen doesn't fill with chips before the text arrives. Then two collapsed disclosures follow it. "Sources (N)" lists only the Sources the answer cites, in tag order, and is left out when it cites none. "How this was answered" holds the Query Scope chips, so an analyst can see what the system answered and dispute it (each Sector phrase with the Companies it resolved to, hover for the Sector table rows it used; the other Companies, the time window, any Section hints and the metric), and every Source the Answer Call was given, cited or not. Each chip opens the Sources panel at its Source; the panel's switcher lists the cited Sources, plus the open one when it isn't cited.

The Sources panel leads with one readable line naming the Source's Company, form type, period and Section ("NVIDIA 10-Q, Q2 FY2025 · MD&A"; the period is the Fiscal Period, or "quarter ended" or "year ended" and the Report Period as a date), with its full label as hover text. The Filing metadata (Filing ID, Company, Form Type, Report Period, Fiscal Period, Section, Item) sits under a collapsed "Filing details" toggle. A passage's flattened tables show as tables, with no header row assumed since the Corpus marks none: a run of table lines (a line starting with `|`, or a data row such as `Revenue | $ | 30,040 |`, which the Corpus writes without the leading pipe) becomes rows split on `|`, their empty edge cells dropped. A line that is just `[...]` (or `[…]`, the gap the retrieval writes between two runs of a chunk) shows as a break, and the rest stays as paragraphs. A Facts Source keeps its table of figures. [`lib/source.ts`](lib/source.ts) holds both readers.

An empty conversation shows the starter prompts and, below them, a line saying how many Companies are covered and how many have two or more years of quarterly Filings, linking to the "What's covered" list on "How it works". The workspace page builds those counts with [`lib/coverage.ts`](lib/coverage.ts) from the committed evaluation export's coverage grid, the data "How it works" reads, so the two pages never disagree; without that summary the workspace shows no coverage line.

Under the latest answer, once it is complete (never while it streams, and not after an error), up to three suggested follow-up questions appear under "Ask next", and clicking one sends it at once, as a starter does. [`lib/followUps.ts`](lib/followUps.ts) builds them from fixed templates over the answer's Query Scope, never from a model, so each question still makes exactly one Answer Call: each Sector phrase gives the group's main risk factors; one Company named outside a phrase gives its risk factors, its revenue and its outlook; several give a comparison of the three. A question asking how something changed is offered only for a Tracked Company, so a Snapshot Company gets its latest revenue instead of a trend, and a suggestion equal to the question just asked is dropped. Each suggestion names its Companies by short name and its group by the question's own phrase, so the backend's rules resolve it as they did the question. Suggestions are not starter prompts and are not in the Golden Set or the Brief Suite.

The thread keeps the reader's place. Sending a question (typed, a starter or a follow-up) scrolls once, to put that question at the top of the thread, and the latest question and its answer always take at least the thread's height, so there is room for the answer below it. Nothing scrolls while the answer streams, so the reader can read its start while the rest arrives. A "Jump to latest" button shows while the end of the thread is below the visible area (an `IntersectionObserver` watches it) and scrolls there on click. A conversation restored after a refresh opens at its last question. Scrolling is smooth unless the user prefers reduced motion.

The conversation is kept in the browser's session storage ([`lib/conversation.ts`](lib/conversation.ts)), so a refresh keeps it and a new browser session starts empty; the backend keeps nothing. It is saved once each answer is complete. "New conversation" in the header clears it, so an old Query Scope can't leak into a new topic.

| `components/AmbientBackground.tsx` | The portfolio's fixed, blurred background glow                                                                                           |

| `lib/source.ts`                    | The Sources panel's readers: a Source's readable heading and a passage split into paragraphs, tables and elisions                        |
| `lib/starters.ts`                  | The six starter prompts, copied from the Brief Suite and the Golden Set                                                                  |
| `lib/followUps.ts`                 | The follow-up suggestions, built from fixed templates over an answer's Query Scope                                                       |
| `lib/conversation.ts`              | Keeps the conversation in session storage                                                                                                |
| `components/HowItWorks.tsx`        | The architecture, the evaluation scoreboard and the coverage grid                                                                        |
| `components/Overview.tsx`          | The plain overview: how an answer is made, the headline numbers and the known limits                                                     |
| `components/TechnicalDetails.tsx`  | The "Technical details" layer: collapsible, linkable sections and the "Expand all" control                                               |

| `lib/evalExport.ts`                | The evaluation export's types and number formats                                                                                         |

| `__tests__/`                       | Vitest and React Testing Library tests                                                                                                   |

The starter prompts are the labelled cases that carry a `starter` object, so every demo prompt is measured: the brief's three questions from the Brief Suite (`data/eval/brief_suite.json`), each taking over the starter of the Golden Set version 1 case it replaces, and three Golden Set cases (`data/eval/golden_set.json`). `__tests__/starters.test.ts` reads both files and fails if the copy in `lib/starters.ts` drifts from them.

## The "How it works" page

`/how-it-works`, linked from the workspace's header, puts the evidence inside the product. It opens with a plain overview for a non-technical reader, its domain terms only as hover text: how an answer is made, in three steps (find the relevant Filing passages, one AI call writes the answer, every claim is cited); "What's covered" (every Company, grouped in plain words into those with two or more years of history, the Tracked Companies, and those with only a few Filings, the Snapshot Companies, under the `#whats-covered` anchor the workspace's coverage line links to); the headline numbers of the round's shipped run on dev (Fact Recall, Faithfulness and the share of Coverage Gaps stated, as rounded percentages, each with a one-line plain meaning and worded as a rough guide on the dev cases, linking to `#scoreboard`; left out until answers have been scored); and the known limits, consistent with [`docs/assumptions.md`](../docs/assumptions.md) (only the provided Filings, no company guidance, no trends for Snapshot Companies, one AI call per question). Then come the architecture (from the Corpus to the one Answer Call, and how it is measured), the evaluation scoreboard on Golden Set version 2 (each retrieval Arm against the Shipped Arm on Evidence Reached, with whether it can ship and the free screen's result; the shipped run beside its Control Run and each generator's scores, cost and latency; and the generator comparison: the Control Run's and each challenger's one-sided sign tests and bootstrap intervals against the shipped generator, and the generator chosen, worded as directional), the Brief Suite (each case's pass or fail, its missed must-state facts and how many never reached the Answer Context), the holdout run (its retrieval and answer scores, shown beside dev's with the small-sample caveat) and the Corpus coverage grid (each Company's Filings by Report Period, Tracked and Snapshot). These technical sections sit under "Technical details", each collapsed by default and opened by clicking its heading; an "Expand all" / "Collapse all" control toggles them all, and a URL fragment naming a section's id (`#architecture`, `#scoreboard`, `#brief-suite`, `#holdout`, `#coverage`) opens it on load and whenever the fragment changes, so a link to the scoreboard lands on it open. On a wide screen the technical layer is wider than the reading column, so the tables fit; each table still scrolls sideways where the screen is too narrow. The coverage grid scrolls both ways in its own area, no taller than about 70% of the screen, so both its scrollbars stay in reach, with its header row and its Company and coverage columns fixed while it scrolls. It is a static page built from [`data/eval-export.json`](data/eval-export.json), which `make eval-export` writes from the harnesses' latest reports (see the root [README](../README.md#showing-the-results-in-the-workspace)). The file is committed and generated, never edited by hand; Prettier skips it.

## Commands

From the repo root, `make install`, `make test`, `make lint` and `make format` cover this app as well as the backend. Inside `frontend/`:

| Command                                                       | What it does                                                    |
| ------------------------------------------------------------- | --------------------------------------------------------------- |
| `npm run dev`                                                 | The dev server on http://localhost:3000 (needs the API running) |
| `npm test`                                                    | The Vitest suite                                                |
| `npm run lint` / `npm run typecheck` / `npm run format:check` | ESLint, TypeScript and Prettier checks                          |
| `npm run build`                                               | A production build                                              |

The tests run against a mocked stream: `fetch` returns the API's UI message stream, so the real `useChat` parses it. A controllable variant holds the stream open after a chosen part, so a test can see an answer in progress. They cover a starter sending on click, Markdown rendering, the short answer (the rest hidden until "Show full analysis", expanding mid-stream while it says the rest is still being written, no control for a one-paragraph answer or one opening with a table or heading, each answer expanded on its own and restored collapsed, the Coverage Gap callout's plain heading and each gap stated once by default), a citation opening its Source in the panel (while the answer streams too, and from the short answer), the panel's readable heading, its collapsed "Filing details" toggle, a passage's flattened table shown as a table and its `[…]` gap as a break, nothing shown beneath an answer until it is complete, "Sources (N)" listing only the cited Sources, "How this was answered" holding the Query Scope chips and every retrieved Source, the panel's switcher, a cited tag that isn't among the Sources shown as unavailable, a Facts Source shown as a table, the conversation surviving a refresh with its disclosures, the "New conversation" control, the scrolling (`__tests__/WorkspaceScroll.test.tsx`, which stubs the scroll, motion and visibility APIs jsdom lacks: one scroll on send and none while the answer streams, a restored conversation opening at its last question, and "Jump to latest" showing, scrolling and hiding), the API's reason shown when it rejects a request, a plain message
