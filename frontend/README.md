# Research workspace (front-end)

The Next.js research workspace: an analyst asks a question, or clicks a starter prompt, watches the answer stream in, and clicks any `[Sn]` citation to open that Source's passage in the side panel. It sits on the stack of the developer's portfolio: Next.js (App Router), Tailwind CSS and the AI SDK's `useChat`. It shares the portfolio's look as well: a dark canvas with a faint grid and an ambient glow, glass cards, Inter with monospaced labels and a sky-blue accent, all defined as theme tokens and a few component classes in [`app/globals.css`](app/globals.css).

Run it from the repo root with `make dev`, which starts the chat API and this app together (see the root [README](../README.md#running-the-full-stack)).

## How it talks to the backend

The browser never calls the chat API directly. `useChat` posts the conversation to this app's own route, [`app/api/chat/route.ts`](app/api/chat/route.ts), which forwards the last messages the prompt uses (the question and the 10 before it, the backend's `HISTORY_TURNS`; older ones are dropped, so a long conversation keeps working), each with its role and text (and, for an earlier answer, the Filing ID each of its Source tags cited, never the passages) to the API's `POST /api/chat` (it reads them with the same helpers in [`lib/chat.ts`](lib/chat.ts) that the workspace uses to read a message's text, Sources and data parts) and streams the API's [AI SDK UI message stream](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol) back unchanged. The API's URL therefore stays on the server. It comes from `BACKEND_URL` (copy [`.env.example`](.env.example) to `.env`); when unset it is `http://127.0.0.1:8000`, where `make api` listens. `make dev` sets it to the API it starts.

Each answer shows only its opening paragraph at first: the direct answer of two or three sentences that the prompt's fixed structure puts first. "Show full analysis" reveals the rest (the comparison table and the per-Company detail), and works while the answer streams, showing the rest live; until the answer completes, the control says the rest is still being written. [`lib/chat.ts`](lib/chat.ts) splits the text at its first blank line, and doesn't split an answer with one paragraph or one whose first block is a heading, list item or table row, which then shows whole with no control. The expanded state is each answer's own and isn't saved, so a restored answer starts collapsed. Once the answer is complete, each Coverage Gap shows below it as a Coverage note ([`components/CoverageGaps.tsx`](components/CoverageGaps.tsx)), under the heading "Coverage notes" (with the term Coverage Gaps on hover) in neutral styling, never above the answer and never while it streams, so the answer leads with its finding. Each gap keeps its fixed wording, its label and the domain terms in it in plain words, with the fixed label or term on hover ([`lib/plainWords.ts`](lib/plainWords.ts)). From prompt v15 the answer has no closing Coverage note and mentions a gap only where it leaves part of the question unanswered ([ADR 0016](../docs/adr/0016-coverage-gaps-shown-by-the-product.md)).

The stream carries the Query Scope and the numbered Sources as data parts before the answer text, so every citation is clickable while the answer is still arriving, in the short answer as in the full analysis. Nothing else shows beneath an answer until it is complete (the Coverage notes included; every answer is, except the last one while the chat is waiting for or streaming it; a restored answer always is), so the screen doesn't fill with chips before the text arrives. Then one collapsed "Sources" disclosure follows it ("Sources (N)", N the Sources it cites; plain "Sources" when it cites none). It opens on a line of Query Scope chips, so an analyst can see what the system answered and dispute it (each Sector phrase with the Companies it resolved to, hover for the Sector table rows it used, and likewise a curated Company Group such as "big tech", hover naming the group; the other Companies, the time window, any Section hints and the metric), and the Sections retrieval searched ("Searched in": one chip per Section with how many Filings it was searched in, then the Filings searched whole, hover for their Filing IDs; left out for an answer saved before the API sent them). Then come the Sources the answer cites, in tag order, and, under a collapsed "Also retrieved (N)", the Sources the Answer Call was given but the answer doesn't cite. Each Source chip opens the side panel's Sources tab at its Source.

The workspace has one right-hand side panel, with two tabs, Sources and Calendar ([`components/SidePanel.tsx`](components/SidePanel.tsx)), and a toolbar that is always visible: on a wide screen a rail on the right edge with a document icon and a calendar icon, on a narrow one a row of buttons above the question box. Clicking an icon opens the panel on its tab, and clicking the open tab's icon closes it. Clicking the Sources icon opens the panel on Sources at the latest answer's first Source, S1 (or says there are no Sources yet), and clicking it again while Sources shows closes the panel; the open tab's icon is highlighted. A citation click always opens the Sources tab at that Source, whatever the panel showed, and the panel's close control closes it. On a narrow screen the panel is a full-screen sheet. The Sources tab numbers every Source the answer was given, S1…SN, wrapping on a long list: the cited ones in the accent colour and the rest muted, each saying on hover whether it is cited, so a Source opened from "Also retrieved" never opens without its number.

The Calendar tab ([`components/CalendarPanel.tsx`](components/CalendarPanel.tsx)) shows one ticker tab per Company that any answer's Query Scope named (by name, ticker, common name or Sector phrase; never a Company only retrieved as a Source), in alphabetical order and styled like the Source tabs, or says no company has been asked about yet. A ticker tab shows that Company's Company Calendar ([`components/CompanyCalendar.tsx`](components/CompanyCalendar.tsx), shared with "What's covered"): a header naming when its fiscal year ends ("Fiscal year ends late January"), then one row per fiscal quarter from its first Filing in the Corpus to its latest, newest first, with its calendar months, its Filing (10-K or 10-Q, or "not in the filings" in grey) and its revenue, each fiscal year's row in bold beside its fourth quarter, and the rows banded by the calendar year the period ends in, so how the fiscal year lines up with the calendar shows at a glance. A hover on a figure shows its Filing ID and the label the Filing prints; a fourth quarter's revenue, derived as the year less its three quarters, is marked "derived". A Snapshot Company's calendar shows its Filings and alignment with one line in place of revenue: "Revenue figures are extracted for companies with two or more years of filings." The calendars come from the committed evaluation export's `companies` section, which the workspace page passes in.

The Calendar follows the conversation, moved by each answer once it completes (`useChat`'s `onFinish`, so never while it streams and never for a restored conversation). The first answer in a conversation whose Query Scope names a Company opens the closed panel on the Calendar at that answer's alphabetically first Company, so the thread doesn't narrow while the answer is still arriving. Closing the panel (its close control, or the open tab's toolbar icon) turns this off for the rest of the browser session, kept in session storage beside the conversation ([`lib/conversation.ts`](lib/conversation.ts)), so neither "New conversation" nor a refresh turns it back on; the toolbar is the way back. While the panel shows the Calendar, each new answer naming a Company selects its alphabetically first. While the panel is closed, an answer naming a Company the conversation hadn't asked about puts a dot on the calendar icon (its hover text adds "new companies") until the Calendar is next opened. An answer whose Query Scope names no Company (the tariffs starter) leaves the Calendar alone, and a citation still opens Sources whatever the Calendar's state.

The Sources tab then leads with the open Source's tag and one readable line naming its Company, form type, period and Section ("NVIDIA 10-Q, Q2 FY2026 (May–Jul 2025) · MD&A"; the period is the Fiscal Period with the calendar months the API sends as `calendarMonths`, or "quarter ended" or "year ended" and the Report Period as a date; a Source saved before the API sent the months shows none), with its full label as hover text. The Filing metadata (Filing ID, Company, Form Type, Report Period, Fiscal Period, Section, Item) sits under a collapsed "Filing details" toggle. A passage's flattened tables show as tables, with no header row assumed since the Corpus marks none: a run of table lines (a line starting with `|`, or a data row such as `Revenue | $ | 30,040 |`, which the Corpus writes without the leading pipe) becomes rows split on `|`, their empty edge cells dropped. A line that is just `[...]` (or `[…]`, the gap the retrieval writes only where it skipped text: chunks next to each other in the Filing reach the panel already joined as one passage, their overlap shown once) shows as a break labelled "passage skipped", and the rest stays as paragraphs, with sentences the Corpus glued together ("earnings.Summary") spaced on display only. A Facts Source keeps its table of figures. [`lib/source.ts`](lib/source.ts) holds both readers.

An empty conversation shows the starter prompts and, below them, a line saying how many Companies are covered and how many have two or more years of quarterly Filings, linking to the "What's covered" search on "How it works". The workspace page builds those counts with [`lib/coverage.ts`](lib/coverage.ts) from the committed evaluation export's coverage grid, the data "How it works" reads, so the two pages never disagree; without that summary the workspace shows no coverage line.

Under the latest answer, once it is complete (never while it streams, and not after an error), up to three suggested follow-up questions appear under "Ask next", and clicking one sends it at once, as a starter does. [`lib/followUps.ts`](lib/followUps.ts) builds them from fixed templates over the answer's Query Scope, never from a model, so each question still makes exactly one Answer Call: each Sector phrase gives the group's main risk factors; one Company named outside a phrase gives its risk factors, its revenue and its outlook; several give a comparison of the three. A question asking how something changed is offered only for a Tracked Company, so a Snapshot Company gets its latest revenue instead of a trend. A suggestion never repeats what the conversation asked: a template is dropped when its kind (risks, revenue or outlook) and Companies match the Query Scope of the question just asked or of any earlier one (Risk Factors planned counts as a risk question, the MD&A as an outlook question and the revenue metric as a revenue question), or when its text equals one of those questions, so after "What are the primary risk factors facing Apple, Tesla, and JPMorgan, and how do they compare?" the comparison of their risk factors isn't suggested. Each suggestion names its Companies by short name and its group by the question's own phrase, so the backend's rules resolve it as they did the question. Suggestions are not starter prompts and are not in the Golden Set or the Brief Suite.

The default view reads plainly: the answer body is 16px, no text is under 12px, and the muted colour meets WCAG AA contrast against the canvas. The header, the empty state and the question box use plain words, and where a domain term of [`CONTEXT.md`](../CONTEXT.md) reaches the default view (a Coverage Gap, a Snapshot Company, the Corpus) it shows as plain words with the term on hover; accessible names that tests and screen readers rely on keep the term.

The thread keeps the reader's place. Sending a question (typed, a starter or a follow-up) scrolls once, to put that question at the top of the thread, and the latest question and its answer always take at least the thread's height, so there is room for the answer below it. Nothing scrolls while the answer streams, so the reader can read its start while the rest arrives. A "Jump to latest" button shows while the end of the thread is below the visible area (an `IntersectionObserver` watches it) and scrolls there on click. A conversation restored after a refresh opens at its last question. Scrolling is smooth unless the user prefers reduced motion.

The conversation is kept in the browser's session storage ([`lib/conversation.ts`](lib/conversation.ts)), so a refresh keeps it and a new browser session starts empty; the backend keeps nothing. It is saved once each answer is complete. "New conversation" in the header clears it, so an old Query Scope can't leak into a new topic.

## The "How it works" page

`/how-it-works`, linked from the workspace's header, puts the evidence inside the product. It opens with a plain overview for a non-technical reader, its domain terms only as hover text: how an answer is made, in three steps (find the relevant Filing passages, one AI call writes the answer, every claim is cited); "What's covered", under the `#whats-covered` anchor the workspace's coverage line links to: a summary line ("54 companies · 13 with two or more years of quarterly filings · 41 with a few filings"), then a search by name, ticker or common name (the export's `commonNames`, taken from the Query Scope parser's alias table, so "Google", "Facebook" and "Coke" find what a question naming them would) whose best match opens a company card (its Sector, a "Two or more years" or "A few filings" badge, the Tracked or Snapshot term on hover, the shared Company Calendar and an "Ask about this company" link to `/?ask=<question>`, which the workspace fills into its question box without sending, then drops from the address), any other matches listed beside it, a plain "isn't in the filings" for a Company on the export's `missingCompanies` list (Wells Fargo, Citigroup) and "No company matches" otherwise; "Show all companies" lists every Company grouped by coverage, filterable by Sector, each row opening its card; the headline numbers of the round's shipped run on dev (Fact Recall, Faithfulness and the share of Coverage Gaps stated, as rounded percentages, each with a one-line plain meaning and worded as a rough guide on the dev cases, the share of gaps stated named the roughest since it counts only the cases with a gap, linking to `#scoreboard`; left out until answers have been scored); and the known limits, consistent with [`docs/assumptions.md`](../docs/assumptions.md) (only the provided Filings, no company guidance, no trends for Snapshot Companies, one AI call per question). Then come exactly three technical sections, each with only the latest results (the history stays in [`docs/evaluation.md`](../docs/evaluation.md)): the architecture (from the Corpus to the one Answer Call, and how it is measured), the evaluation scoreboard on Golden Set version 2 (each retrieval Arm on the current code against the Shipped Arm on Evidence Reached, with whether it can ship and the free screen's result; the latest round's shipped run beside its Control Run and each generator's scores, cost and latency; and that round's generator comparison: the Control Run's and each challenger's one-sided sign tests and bootstrap intervals against the shipped generator, and the generator chosen, worded as directional) and the latest holdout run (its retrieval and answer scores, shown beside dev's with the small-sample caveat). There is no Brief Suite, no earlier round's comparison and no Corpus coverage grid: "What's covered" shows the coverage. These technical sections sit under "Technical details", each collapsed by default and opened by clicking its heading; an "Expand all" / "Collapse all" control toggles them all, and a URL fragment naming a section's id (`#architecture`, `#scoreboard`, `#holdout`) opens it on load and whenever the fragment changes, so a link to the scoreboard lands on it open. On a wide screen the technical layer is wider than the reading column, so the tables fit; each table still scrolls sideways where the screen is too narrow. It is a static page built from [`data/eval-export.json`](data/eval-export.json), which `make eval-export` writes from the harnesses' latest reports (see the root [README](../README.md#showing-the-results-in-the-workspace)). The file is committed and generated, never edited by hand; Prettier skips it.

## Commands

From the repo root, `make install`, `make test`, `make lint` and `make format` cover this app as well as the backend. Inside `frontend/`:

| Command                                                       | What it does                                                    |
| ------------------------------------------------------------- | --------------------------------------------------------------- |
| `npm run dev`                                                 | The dev server on http://localhost:3000 (needs the API running) |
| `npm test`                                                    | The Vitest suite                                                |
| `npm run lint` / `npm run typecheck` / `npm run format:check` | ESLint, TypeScript and Prettier checks                          |
| `npm run build`                                               | A production build                                              |

TypeScript runs side by side, as the [TypeScript 7.0 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-6.0) recommends: `@typescript/native` is TypeScript 7, whose `tsc` runs `npm run typecheck`, and `typescript` is an alias for `@typescript/typescript6`, which keeps TypeScript 6's API for the tools that import it (typescript-eslint, which doesn't support 7.0 yet, and the type check in `next build`). Drop the alias once typescript-eslint supports TypeScript 7.
